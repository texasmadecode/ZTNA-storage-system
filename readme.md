# Zero-Trust Host Attestation & Endpoint Authentication Gateway

A lightweight, containerized Zero-Trust Network Access (ZTNA) authentication prototype designed for small business Windows Server environments. This security engine implements server-side cryptographic SHA-256 one-time credential hashing alongside deep client-side WMI hardware footprint extraction to prevent credential stuffing and session hijacking from unauthorized remote endpoint devices.

## 🔒 Security Architecture & Logic

Most traditional network gateways rely solely on a username and password, creating a single point of failure if credentials are leaked or brute-forced. This system implements a strict **Zero-Trust policy** ("never trust, always verify") by split-validating two layers of integrity before granting access to network file assets:

1. **Hardware-Level Device Attestation:** Prior to evaluating user passwords, the gateway challenges the connecting client device. The system natively triggers a Windows Management Instrumentation (WMI) query to parse the host motherboard's permanent, factory-stamped `UUID`. If the unique hardware identifier does not perfectly match the server's authorized endpoint registry, the connection is instantly severed and a critical event is logged—rendering stolen passwords useless from hacker machines.
2. **Cryptographically Secure One-Time Passwords (OTP):** Account provisioning utilizes Python's cryptographically secure `secrets` library to extract true high-entropy randomness generated by system electrical noise. The raw string credential is shown to the administrator exactly once, instantly run through a one-way `SHA-256` hashing algorithm, and stored securely at rest. 
3. **Automated NTFS Access Control Lists (ACL):** Upon successful authentication, the script utilizes Python's `subprocess` engine to safely orchestrate native background Windows shell processes. It calls the Windows `icacls` utility to dynamically grant or revoke strict granular file folder permissions (`Read-Only`, `Full Control`, or `Deny`) directly into the Windows Server architecture.
4. **Isolated Auditing & Trail Compliance:** Every connection handshake lifecycle, validation pass, or administrative policy alteration is appended to an explicit local auditing ledger (`server_audit.log`) to preserve an untampered trail for security compliance monitoring.

## 🛠️ DevOps Deployment & Continuous Integration

This project uses modern DevOps practices to ensure cross-platform consistency and automated security testing:

### 📦 Docker Containerization
The entire codebase is containerized using an official minimal `python:3.12-slim` Linux workspace. This isolates the authentication script from the host server, preventing environmental drift and ensuring the system executes reliably in any deployment environment. 

### 🚀 CI/CD Automated Cloud Pipelines (GitHub Actions & GHCR)
The repository contains an automated workflow pipeline (`test.yml`) that executes on every single code modification:
* **Linting & Testing:** GitHub automatically provisions a fresh cloud server instance, pulls down the source code, builds the container image locally, and executes the security gatekeeper suite to ensure all internal module imports work perfectly.
* **Production Packaging & Release:** Once tests clear with a green pass status, the cloud agent securely signs into the **GitHub Container Registry (GHCR)** using runtime actor macros, packages the stable build version, and automatically releases a public target image to the software registry.

## 💻 How To Run the Project

### Local Python Execution
To run the security simulation framework natively on your machine, navigate to your root folder and execute the application driver:
```bash
python main.py
```

### Building & Running via Docker Locally
To build the immutable image profile and run it inside an isolated local sandbox:
```bash
# Build the image and compile environment binaries
docker build -t secure-gatekeeper .

# Fire up the container instance and remove volatile runtime state upon termination
docker run --rm secure-gatekeeper
```

### Pulling from the Official GitHub Cloud Package Registry
Once built by the cloud automation pipeline, you can fetch and run the official production-grade package release on any target machine worldwide using a single terminal instruction:
```bash
docker run --rm ghcr.io/texasmadecode/ztna-storage-system:latest
```
